01安装

三个包一次装完，都是 bottle，无编译。

brew install task timewarrior taskwarrior-tui

==> Pouring timewarrior--1.10.0.arm64_tahoe.bottle.tar.gz
==> Pouring taskwarrior-tui--0.27.0.arm64_tahoe.bottle.tar.gz

验证：

3.5.0
1.10.0
已带补全 Homebrew 会把 zsh completion 装到 /opt/homebrew/share/zsh/site-functions，新开终端即生效。

02初始化

2.1 先给 Taskwarrior 一个 rc 文件

3.5 找不到 ~/.taskrc 会直接拒绝执行（Cannot proceed without rc file.）。最小配置：

# ~/.taskrc
confirmation=no
dateformat=Y-M-D
weekstart=monday

数据库会自动建在 ~/.task/taskchampion.sqlite3，不用手动初始化。

2.2 初始化 Timewarrior

首次运行会问两个问题（建配置、建数据库），交互式终端直接答 yes。脚本化就喂进去：

printf 'yes\nyes\n' | timew summary :day

生成 ~/.config/timewarrior/timewarrior.cfg 与 ~/.local/share/timewarrior/data。

2.3 别名、fzf 与速查表

统一放进 ~/.config/zsh/task-aliases.zsh，~/.zshrc 里 source 一行：

source ~/.config/zsh/task-aliases.zsh
命令作用
t-help打印全部命令与中文注释，随时查
t-help due按关键词过滤条目
tffzf 选任务，看详情
tf donefzf 选任务并完成

别名 t / tt / tw 也定义在这个文件里。

03每日闭环

四步，一天只花几分钟。排序交给 urgency，不要自己盯着列表纠结。

  1. 收集：想到就丢进去

    t add "回邮件给客户" due:eod +work
t add "每周复盘" recur:weekly due:fri
    Created task 1.
Created task 2 (recurrence template).
Creating recurring task instance '每周复盘'

    只写描述也能用。due、标签、项目都是可选的，先收进来比分类重要。

  2. 排期：看 urgency 排序后的前几条

    t next
t next limit:5
    ID Age P Project Due Description        Urg
-- --- - ------- ----- ---------------- ----
 1   - H work    12h   回邮件给客户     15.6
 2   -   P7D   6d     每周复盘          5.8

    Urg 由 due、priority、标签、age 加权得出。你只需要做最上面那条。

  3. 执行：开工打点，完成落账

    t 1 start
t 1 done
    Starting task 1 '回邮件给客户'.
Started 1 task.
Completed task 1 '回邮件给客户'.

    start 会给任务打 Active 标记并抬高 urgency，next 里一眼能看到正在做什么。

  4. 收尾：看今天完成了什么

    t completed
tw summary :day
    ID UUID     Created    Completed  Age Tags Due        Description
-- -------- ---------- ---------- --- ---- ---------- -----------
 - 1eb23c32 2026-11-06 2026-11-06 15s work 2026-11-06 回邮件给客户

    3.x 的已完成任务 ID 显示为 -，用 UUID 定位。复盘按时间范围取：

    t completed end.after:today-7days
tw summary :week

04语法速查

需求写法说明
今天结束前due:eod23:59:59
明天due:tomorrow次日 00:00
N 天后due:2d显示为 2d
指定日期due:2026-11-10当天 00:00
标签+work可多个
项目project:work单值，可分级 a.b
优先级priority:HH / M / L
重复任务recur:daily另有 weekly / monthly
过滤t +work due:today条件叠加
看某项目t project:work直接用报告名也行
搜索t /周报/描述模糊匹配
修改t 1 modify due:tomorrow priority:L一次改多个属性
撤销t undo回退上一条修改
集中上下文t context define work +work之后自动附加 +work
关闭上下文t context none恢复全局视图
due 的边界 due:today 是今天 00:00，加上去立刻显示逾期（实测 -11h）。 想要“今天结束前”，用 due:eod。

05时间账本

Timewarrior 独立于 Taskwarrior：t start/done 记任务状态，tw start/stop 记时间区间。两者不会自动联动。

tw start 写周报
tw stop
tw summary :day
tw summary :week
tw tags
Wk  Date       Day ID Tags   Start    End      Time   Total
--- ---------- --- -- ------ -------- -------- ------ -------
W45 2026-11-06 Fri @1 写周报 11:51:17 11:51:24 0:00:07 0:00:07

开工时想一步到位，就在同一行串起来：

t 1 start && tw start 写周报
零时长会报错 同一秒内 tw start 后立刻 tw stop，会得到 The end of a date range must be after the start. 真实计时不受影响。

06TUI 看板

tt        # 等价于 taskwarrior-tui

? 打开内置键位表，q 退出。CLI 和 TUI 操作的是同一个数据库，可以混用。

必须在真实终端里跑 后台启动或把 stdout 重定向到文件，crossterm 会 panic：reader source not set。

07备份与迁移

JSON 是稳定的交换格式，跨版本、跨机器都能用：

t export > ~/task-backup.json
t import ~/task-backup.json
Imported 1 tasks.
不要直接同步 SQLite 文件 3.x 的数据是 ~/.task/taskchampion.sqlite3。用 rsync、Syncthing 或 git 直接同步这个文件， 官方明确不保证一致性。多机同步请用 task sync（需要服务端），单人单机用 export 备份即可。

08踩坑

现象原因处理
Cannot proceed without rc file. 没有 ~/.taskrc 创建最小 rc 文件
任务一加就显示逾期 due:today 是当天 00:00 改用 due:eod
Timewarrior 卡在 yes/no 首次初始化询问 交互答 yes，或 printf 'yes\nyes\n'
reader source not set TUI 不在真实 tty 中 直接在终端运行 tt
找不到教程里的 pending.data 那是 2.x 的纯文本存储 只看 3.x 文档，数据在 SQLite
每次启动提示升级 3.5 的 release note 未读 t news 一次，提示消失
TASKRC override: 空提示 环境里设了空 TASKRC unset TASKRC
下一步 单人单机到这里就够了。需要多机再考虑 task sync（3.5 支持 git 后端，但配置和加密密钥要求更多）。 如果你要的是“人类可读、能手改、能 diff”的任务文件，Taskwarrior 3.x 不是这个方向。
